# 个人岗位 RAG 网页真实场景验收

日期：2026-09-26。对象为主工作区个人网页入口，固定链路为 `hybrid_rerank + model`，模型配置来自本机既有 `.env`。本轮获得用户明确授权使用少量付费 API；没有打印、复制或提交 Key。

## 费用与执行边界

- 每个请求自动重试固定为 0；初始单次输出上限 900 tokens，发现过紧后调整为 1500 tokens。
- 初始完整套件含 4 个 RAG 问题和 1 个确定性市场统计；随后只重跑初次截断的 3 个 RAG 问题，没有重复成功案例。
- 共发生 7 次真实模型请求。3 次生成完整答案，4 次因 `finish_reason=length` 安全失败；市场统计 1 次、未调用模型。
- 新版 API 能保存截断请求的脱敏 `failure_type` 和 usage。当前报告中可精确汇总的四次 provider usage 为 7,063 tokens：LangGraph 1,084、多技能截断 2,540、候选匹配 2,046、时效边界 1,393。900-token 首轮的另外三次截断发生在该错误字段接通前，无法从保存报告精确汇总，因此 7,063 不是本轮总消耗。
- 原始机器报告保留在本地忽略文件 `output/live-web-scenarios-20260926.json` 与 `output/live-web-scenarios-20260926-focused-rerun.json`；网页 trace 保留在忽略的 `projects/research_assistant/logs/personal_live_web_trials.jsonl`。

## 本轮修复

- 个人入口不再继承父进程的非零重试或过大输出预算，固定零重试和 1500-token 输出上限。
- 通用模型适配装配支持 `MODEL_MAX_TOKENS`，并保留 `finish_reason=length` 的拒绝合同。
- Prompt 新增默认简洁约束；它降低冗长风险，但本次证明不能单独保证复杂比较一定低于 token 上限。
- API 对截断返回脱敏的结构化失败类型与 usage；网页显示可操作错误，不再只显示笼统 503。
- 新增显式付费、零重试、最多四次模型调用的五场景运行器；成功回答与安全失败分开记录。

## 证据边界与下一步

本轮验证了当前机器、当前模型配置、当前岗位快照上的 localhost HTTP、真实 ReRank、外部生成、引用结构、usage 和时效边界。它不是开放世界准确率、重复稳定性、并发、生产 SLO 或费用账单证明。

唯一后续工程问题是复杂多证据比较：先固定当前失败案例，再比较“压缩证据”和“检索后分步归纳”两种方案，在相同岗位快照、Top-K 和 1500-token 上限下选择；不直接继续放大 token 预算。
